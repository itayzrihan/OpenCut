# Full Auto Edit on routed podcast shorts

All three requested jobs stopped at preflight, before completing any editing stage. They captured scenes with an empty main video track: the selected podcast camera cuts were enabled clips in overlay tracks, with disabled alternatives, separate processed microphone tracks and existing timed captions. The legacy preflight rejected them as an already edited project.

The existing canonical `project.classic.automation.edit` capability now supports `prepare` with explicit project, scene and revision. It accepts only an isolated automation worker at checkpoint zero. For a routed scene without main clips, it promotes the enabled, visible, non-overlapping camera cuts to the main track, preserving identities, source intervals and disabled alternatives. It retains microphone timing, DSP, caption sources and effect tracks. It freezes take assembly metadata in the worker; the original source assembly remains untouched. Unsupported retiming, animated transforms, locked targets and ambiguous overlapping compositions reject atomically. Registry dry run, cancellation, undo and optimistic revisions remain in force.

The browser invokes that canonical preparation after font/model checks. Durable workers reuse saved timed transcripts. The existing source-camera-only silence tool is not run against muted camera audio while separate microphones are audible: the synchronized microphone mix and existing speech boundaries are retained with an explicit result note. This is a conservative hold, not a claim that microphone silence analysis was performed. Legacy direct Smart Takes preparation remains unchanged.

Regression coverage exercises the native capability and reads state through `app.state.read`, including selected/disabled angles, external audio, source isolation, dry run, undo and overlap rejection. Host tests cover retained transcript, microphone mix and checkpoints; existing Full Auto and Auto Texts suites cover resume and legacy behavior. The Auto Texts test fixture was updated for the existing effective-scene canvas getter.

The configured `background-three` check also requires all three original jobs to finish 10/10, publish new 1080×1920 scenes, retain exact chosen camera intervals and microphone timing/DSP, and leave every original scene and global project settings unchanged. It verifies the exact deployed source fingerprint. Live playback evidence is recorded separately; no export or exhaustive human listening is claimed.

Live retry also exposed legacy caption parameter slots containing null. Rust accepts those stored defaults, while the typed Timeline Source adapter correctly rejects explicit null parameters. Serialization now omits only those null slots (the established default semantics), retaining zero, false and empty strings without mutating source state. A roundtrip regression covers this case. Jobs that reached the framing boundary resume at checkpoint one.

A subsequent stop at music checkpoint eight exposed the detached HTML audio metadata probe. Failed probing had been converted to duration zero, producing a misleading short-song error. Music verification now reads encoded audio metadata through the bounded range-reader used by the media engine, independent of DOM playback and background autoplay. Cancellation/30-second timeout dispose the reader, invalid durations still reject, and read errors remain distinguishable from genuinely short files. Tests cover real WAV range IO in a Node process with no DOM, invalid metadata and cancellation. Existing stage checkpoints allow a music-only retry.

All three original jobs ultimately completed 10/10 and published additional scenes: refund follow-up 33.84 s, December deadline 58.52 s, reserve-duty distinction 40.36 s. The first music retry resumed checkpoint eight; the other two completed without repeating their preparation. Representative playback advanced 15.03 s with the two original microphone tracks retained. Final configured verification covers 31 Rust and 58 host tests, production TypeScript, unchanged source scenes/settings, exact camera intervals and microphone DSP, and deployed source fingerprint. The full test-inclusive TypeScript configuration still reports existing type errors in canonical-unified-audio.test.ts and the prior project-session fixture; production types and the runtime regressions pass.

# OpenCut Render Queue

Classic-only feature, using the canonical OpenCutRuntime and existing Classic compositor. No rewrite parity or migration is asserted.

The selected editor invokes `project.classic.export.capture` synchronously at its current canonical revision. This freezes the complete project/scene dependency graph, HyperFrames source and media bindings before any asynchronous host IO. An authenticated, account-scoped host instantiates the same canonical OpenCutRuntime, restores its durable application bytes, invokes `render.queue.edit`, and atomically persists the result under an interprocess filesystem lock. The host does not implement a second queue state machine. Queue state is `EditorDocument.renderQueue`, validated by Rust and readable through `app.state.read`. Export options are typed; the snapshot and options have a SHA-256 integrity hash. Pending settings changes recompute this hash explicitly.

An independent, opener-free browser window claims one queued job at a time. It runs the production GPU compositor and existing disk-backed sound/effects pipeline in a fresh canonical editor realm, without acquiring a source project write lease or saving source project/history. Existing direct export remains available. Subsequent edits or navigation in the original editor have no access to the queued snapshot. Each finished job reloads its own renderer realm to release decoders/GPU resources before claiming the next job.

Host file bindings are frozen at enqueue. Copied media is retained by a hard link; fonts are copied. External linked media remains linked at its original path and is checked for size/mtime changes before streaming. Relinking a source editor does not redirect a queued job. Removing a memory card or changing linked source bytes causes a visible failure, not silent use of replacement footage. Source media is never copied wholesale from external cards.

A worker attempt ID fences progress and completion. The host serializes claims across processes/windows. Progress heartbeats renew the active job, cancellation is acknowledged by that worker, and an absent worker becomes failed after 120 seconds. Retrying uses the original snapshot and recipe. Results upload as a bounded streaming user-export file, are fsynced and atomically renamed before completion, and download by authenticated job ID. No arbitrary output paths, credentials or shell tools are exposed. These potentially multi-gigabyte user exports are not agent preview artifacts; existing bounded ArtifactStore previews remain unchanged.

The queue/history and completed files survive editor refresh and host restart. Encoding requires the separate renderer window to remain open or minimized; closing it interrupts the active job, whose frozen snapshot remains retryable. The compositor and editor still share the computer's CPU/GPU and disk bandwidth, so background rendering cannot guarantee zero performance impact. Queue history is bounded to 200 retained jobs in this first implementation.

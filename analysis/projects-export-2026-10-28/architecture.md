# Library export

Classic-only follow-up to Render Queue. Selected-project actions expose Export alongside Duplicate/Delete, including the compact action menu. Editor and library use one ExportSettingsFields/ExportPlanSummary projection for format, quality, smart/project resolution, MP4 encoding and audio. Library supports a saved scene per project and per-project recipe overrides.

The authenticated host reads each source through the canonical editor-session read policy, preferring saved.project over obsolete legacy/top-level data. It never acquires source write ownership. A temporary canonical OpenCutRuntime validates attachment, captures the immutable dependency graph and calculates the existing native export plan. Preview exposes only project/scene summaries and settings. Enqueue rechecks the saved storage revision before capturing and freezing media through the established queue host. Stale selections fail visibly and can refresh; another editor's unsaved changes are explicitly excluded.

Direct delivery extends canonical QueuedRender with an additive, default-queue delivery enum and destination filename. Direct jobs require a selected destination, are claimed explicitly rather than consumed by background queue windows, retain the same attempt fencing and cancellation, and publish no server outputId. Normal queue jobs remain FIFO. One renderer runs at a time; a current render may finish before a direct job starts. Direct settings remain fixed after choosing a destination.

Direct exports use user-gesture native File System Access pickers: one file for a single project; a directory for multiple projects. Existing directory filenames receive a distinct suffix instead of silent overwrite. File handles remain ephemeral host IO. Each direct job receives a disposable EditorCore instance bound to its own canonical runtime and frozen snapshot. Autosave is stopped before loading; the visible editor singleton and source ownership are untouched. The existing compositor/audio pipeline writes directly to the selected handle, and completion is acknowledged after the file commits. The disposable instance releases managers, canonical state and media when finished. Parent progress/cancellation comes from the canonical queue. No source editor project, history, settings or lease is changed. Background queue delivery remains in an opener-free renderer window.

Direct delivery requires Chrome/desktop File System Access support and the library page to stay open. Other browsers retain background Render Queue downloads. This does not implement rewrite parity, source-project migrations, or changes to Duplicate/Delete behavior.

Live testing caught two host issues before completion. Copied uploads expose their resolved local file path through listMedia; binding checks now compare against getMediaFile.path rather than the linked-only stored sourcePath. Copied-source regression verifies frozen hardlinks and stale-binding rejection. Registry construction also took approximately two seconds per request under local load. The queue host now reuses one canonical runtime per module, with a local serial gate plus the existing cross-process filesystem lock. Every transaction restores the locked account bytes (or an empty runtime for a new account); account documents are not mirrored in a separate state store. A two-account regression proves that reuse cannot leak jobs between accounts. The focused nine-test web suite completes in approximately twelve seconds after this change.

Direct work starts through a lazy module import in the library page. Jobs are explicitly claimed and run sequentially, sharing canonical progress, cancellation and attempt fencing with the Render Queue. Native file handles are never serialized into project or queue state.

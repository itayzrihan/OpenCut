# Director chapter generation and Seamless batches

The canonical `generative.chapterPlans` collection owns chapter requests, exact script/version and approved reference captures, direction digest, and ordered provider links. The production handoff is an immutable snapshot, and stale source versions prevent preparing a new chapter batch. Media imports remain ordinary separate assets. The combined collection is a persistent metadata asset referencing those originals; its local sequential preview performs no server rendering. Inserting the collection calls the shared canonical clip insertion transaction, retaining every cut and one Undo boundary. Podcast unified angles are unchanged.

`project.generative.chapters.build` uses the current selected model's advertised durations. Long source rows split into time windows no longer than its maximum, and the final window uses the smallest supported duration that fits. Whole words are assigned proportionally; concatenating the segments preserves every source/Latin byte. This timing is explicitly estimated and shown for human review, not represented as forced alignment or verified speech timing. No transliteration is invented. Source-window and generated durations are displayed separately per chapter and in total before approval; generated durations round up to model-supported values. Full generated clips remain intact to avoid cutting speech. Exact source pacing requires reviewing/refining the canonical rows and provider results; no automatic speech alignment is claimed. Up to 32 output chapters per plan, 16 collections and 200 provider history links per project are bounded. The canonical builder performs no IO. `project.generative.request` operation `prepareChapters` exposes the same source-checked preparation through the internal agent/MCP host, without an approval operation.

Preparation freezes per-request payloads and a manifest digest. Human confirmation and PIN approve exactly that manifest; up to three independent jobs run concurrently. Each paid request has a durable exclusive submission claim. A stopped batch worker is surfaced as paused; reopening first reconciles accepted jobs with free status checks before sending unsent requests. Unknown submission outcomes never retry automatically. Cancellation stops queued requests only: accepted provider jobs can still finish and bill. The renewable worker lease and per-request durable claim work across Node workers/restarts. Credentials/PINs do not enter editor state or tool output.

Reference content/style guidance and exact first/last frames are explicit separate modes. Independent chapters share approved identity/style references and preceding visual descriptions; perfect boundary continuity is not promised. Seamless Connect captures source boundaries locally and prepares up to ten selected cuts. It validates all frozen source anchors, then inserts generated bridges from right to left in one canonical transaction so earlier source anchors remain valid. Any stale anchor, missing output or locked affected track rolls back the entire batch. Collection context actions can insert its clips and open the same Seamless dialog.

Image generation validates the selected live OpenRouter model's image output, chat-completions endpoint, and image-input support when references are used. It uses the model's advertised image/text output modalities. Images can share a manifest (up to ten) and the same inline human PIN approval. Stable operation IDs return the existing identical request and reject changed payloads.

Official contract evidence (read-only, 2026-11-10):

- [OpenRouter video generation](https://openrouter.ai/docs/guides/overview/multimodal/video-generation): asynchronous submit/status/content, live model constraints, `frame_images` takes precedence over `input_references`.
- [Reference-to-video](https://openrouter.ai/docs/cookbook/video-generation/reference-to-video): content/style references differ from exact frame anchors.
- [Seedance 2.5](https://openrouter.ai/bytedance/seedance-2.5): the observed current catalog supports 4–30 seconds, but application choices and validation read the live catalog.
- [Model discovery](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties): `architecture.input_modalities`, `architecture.output_modalities`, and supported endpoints.
- [Image generation](https://openrouter.ai/docs/guides/overview/multimodal/image-generation): models with image outputs and reference support.

Validation uses mocked provider calls only: no real image or video generations or charges. Rust registry tests cover exact text, automatic 90-second splitting, stale captures, host preparation, app.state.read readback, archive restore/Undo/Redo, collection insertion, and multiple Seamless cuts. Transport tests cover approval, bounded concurrency, cancellation, claim replay, live models and mode validation. Real visual quality, lip sync and generated boundary continuity remain provider outcomes and have not been claimed as verified by mocked tests.
